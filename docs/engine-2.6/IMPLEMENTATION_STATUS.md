## Persistent prepared-preview cache

`src/board/derivedDiskCache.ts` stores **derived PNG previews of eligible TIFF assets** in the WebView/browser profile's IndexedDB database `art-equation-derived-engine-26`. It uses the profile's disk; no claim is made that this particular disk has been measured as an SSD. Native prepared image pyramids already remain reusable project-local derivatives.

- TIFF key includes SHA-256 of original source bytes plus decoder/output version. Changing a file at the same path cannot reuse its previous preview.
- Maximum 256 MiB of encoded preview payload, 128 entries and 32 MiB per entry. Schema 2 separates PNG blobs from the small LRU metadata ledger; eviction never reads the complete blob collection. Atomic writes serialize cache admission. Reads use readonly transactions; recency updates are best effort. Closed/version-changed connections are reopened. Database metadata/OS overhead is outside the encoded-payload count.
- Original TIFF input is capped at 16 MiB and declared decoded dimensions at 8 megapixels. Larger TIFFs use the existing prepared/tiled-image workflow instead of unbounded worker allocation.
- Cache PNG dimensions/pixels must decode successfully. Corrupt cache data is discarded and recreated from the original. Invalid ledger rows cannot poison the byte accounting.
- Quota/blocked-profile/storage failures fall back to original decoding. Clearing previews cannot delete source files, project databases, board saves or recovery snapshots.
- Persistent preview lookup still reads/hashes source bytes. It avoids repeated TIFF decoding/PNG generation, not all disk I/O. Visible pixels remain in memory/GPU resources; panning is not redirected through disk storage.
- Settings → Rendering shows usage, worker occupancy, **Clear prepared previews**, and native capability inspection. Preparation and cache hit/miss evidence is retained in diagnostic telemetry available to the embedded Codex inspector.

The cache is not a replacement save format, and it does not alter the existing continuous-save/recovery-interval preferences.

## Additional correctness defect found

The native semantic-index regression intermittently failed to retrieve an indexed vector as its best match. The disposable HNSW graph is now constructed with metric L2 distance on normalized vectors, dispersed stable insertion order and less upper-layer concentration while retaining the diversity heuristic. Original record order, vectors and authoritative dot-product scores are unchanged. Version-1 derivatives fall back to exact search until rebuilt.

Publication checks sixteen distributed known vectors and refuses a derivative that cannot retrieve itself. Exact authoritative search remains available when a derivative fails validation. Tests also verify seven separated known queries after persistence, damaged-sidecar fallback and rebuild. Three consecutive targeted correctness runs and the full native suite passed after the change; this is not a universal ANN recall guarantee or a performance result. Approximate-query recall beyond the verified corpus remains its own qualification.

## Startup preparation and isolation

The app starts one background helper at launch; main-window creation does not wait for it. The helper creates wgpu/OpenCL contexts and compiles dimension-independent shaders once, validates a tiny known fixture, then retains those resources. Settings shows warmup state/cost and enables comparisons after readiness. Native logs and capability inspection expose this state to Codex. Each job still includes source/output copies, CPU validation and helper communication; these costs are not hidden. No graph, board, source-media or save mutation occurs. One job is admitted, a 60-second driver deadline applies, input is limited to 4 megapixels and parent exit/EOF releases helper resources. Contexts are explicitly disposed before Rust TLS destruction.

The Gemini compute review timed out and is not credited as a completed review. Earlier cache-review feedback informed the verified metadata-ledger/connection corrections. New driver execution and cleanup are verified locally. CUDA/resource sharing and tile-damage presentation remain open implementation stages.
